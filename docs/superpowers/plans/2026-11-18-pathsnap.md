# PathSnap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build an end-to-end GPS map-matcher (classifier + HMM) served via FastAPI and shown in a Streamlit UI, with report artifacts.
**Architecture:** The offline pipeline turns each trip into a table of (point, candidate) rows with features and labels. Models are trained on that table, the best one is tuned, and Viterbi decodes each sequence. The API wraps the same pipeline for one trip.
**Tech Stack:** Python 3.12, pandas, shapely, pyproj, scipy, scikit-learn, LightGBM, Optuna, folium, FastAPI, Streamlit.
**Spec:** `docs/superpowers/specs/2026-11-18-pathsnap-design.md`

## Global Constraints
- Never read `data/evaluator_test/*.route` outside `api/evaluate.py`. Ground truth must not reach the UI.
- Training uses `data/train` only. The 10 student_test trips are for comparison and tuning β only.
- Distances are in metres (EPSG:32632). Use R=50 m, K=8, a 3 m stationary filter and 60 s gap splits.
- Fix all seeds at 42. Every reported number must come from a file in `experiments/`.

## Review Focus
1. A trip with a huge time gap (train 42 h gap): segments must be split and must not crash the HMM. Covered by test_split_on_gap.
2. A GPS point with zero candidates: features must skip it, and the HMM must break the chain and leave the arc as -1. Covered by test_viterbi_no_candidates.
3. An evaluator trip with no `.route` file: the API must still predict and return metrics as null.
4. Very large trips (19k points, 300k arcs): candidate generation must use the STRtree and finish in under about 30 s.
5. The UI cannot reach the API (Wi-Fi isolation): Streamlit must show a clear error, not a stack trace.
